# ソフトウェア開発の全体像

前回は、JavaScriptやPythonなどのプログラミング言語の特徴と、開発目的に応じた言語の選び方を学びました。

しかし、実際のソフトウェア開発では、プログラミング言語を一つ選ぶだけでアプリケーションが完成するわけではありません。

例えば、ToDoアプリでタスクを追加すると、画面に新しいタスクが表示されます。さらに、ページを閉じて再び開いても、保存したタスクが残っていることがあります。

このような機能は、どのような仕組みで実現されているのでしょうか。

この授業では、Webアプリケーションを例に、**ソフトウェアを構成する技術と、それらがどのように連携しているのか**を学びます。

## この授業で学ぶこと

- フロントエンド・バックエンド・データベースの役割
- APIを通じたデータのやり取り
- HTTPのリクエストとレスポンスの基本
- ローカル環境と公開環境の違い
- アプリケーション全体の構成を考える方法

## 1. ソフトウェアは複数の技術で構成されている

Webアプリケーションは、画面を表示する処理、データを扱う処理、データを保存する仕組みなどを組み合わせて作られます。

代表的な構成要素には、次のようなものがあります。

| 構成要素 | 主な役割 | ToDoアプリの例 |
| --- | --- | --- |
| フロントエンド | ユーザーが操作する画面を提供する | タスクの入力・一覧表示 |
| バックエンド | リクエストを受け取り、必要な処理を行う | タスクの登録・取得 |
| データベース | データを保存・管理する | タスクの内容や完了状態を保存 |
| API | ソフトウェア同士が機能やデータをやり取りするための窓口・取り決め | タスクの登録や取得を依頼する |

これらは役割を表す言葉であり、必ずしも別々のコンピューターで動かす必要はありません。

また、アプリケーションによっては、バックエンドやサーバー上のデータベースを用意せずに実現できるものもあります。

## 2. フロントエンドとバックエンド

### フロントエンドとは？

フロントエンドは、ユーザーが直接操作する部分を担当します。

Webアプリケーションでは、HTML・CSS・JavaScriptなどを利用して画面を構築します。

例えば、ToDoアプリでは次のような機能を実装します。

- タスクを入力する
- 追加ボタンを押す
- 登録されたタスクを一覧表示する
- 完了したタスクの見た目を変更する

フロントエンドでは、ユーザーの操作に応じて画面を更新することが重要です。

### バックエンドとは？

バックエンドは、ユーザーから直接見えない場所で、アプリケーションに必要な処理を行う部分です。

Webアプリケーションでは、サーバー側で動作するプログラムがバックエンドを担当することがよくあります。

例えば、次のような処理があります。

- ユーザーから送られたデータを検証する
- タスクを登録・更新・削除する
- ユーザーが操作できるデータか確認する
- データベースから必要な情報を取得する

バックエンドは、JavaScript・TypeScript・Python・Java・Goなど、さまざまな言語で開発できます。

### なぜ役割を分けるのか？

例えば、タスクを追加する際、画面に文字を表示するだけならブラウザー内の処理で実現できます。

しかし、複数の端末で同じタスクを確認したり、ユーザーごとにデータを管理したりする場合は、サーバー側で処理する構成が候補になります。

**どの処理をどこで実行するかは、必要な機能によって変わります。**

## 3. データベースとは？

データベースは、データを整理して保存・管理するための仕組みです。

例えば、ToDoアプリでは次のようなデータを扱います。

| id | title | completed |
| --- | --- | --- |
| 1 | レポートを書く | false |
| 2 | 買い物に行く | true |
| 3 | 授業の復習をする | false |

データベースを利用することで、必要なデータの検索・追加・更新・削除などを行えます。

代表的なデータベース管理システムには、PostgreSQL、MySQL、SQLiteなどがあります。

### データベースは必ず必要？

必ずしも必要ではありません。

例えば、ブラウザーの `localStorage` を利用すれば、簡単なToDoアプリのデータをそのブラウザーに保存できます。

一方、複数端末でデータを共有したり、大量のデータを管理したりする場合には、サーバー側のデータベースを利用する構成が考えられます。

重要なのは、**保存するデータの種類や利用方法に応じて、適切な保存方法を選ぶこと**です。

## 4. APIとは？

API（Application Programming Interface）は、ソフトウェアが別のソフトウェアの機能やデータを利用するためのインターフェースです。

Webアプリケーションでは、フロントエンドとバックエンドがHTTPを利用したWeb APIで通信することがよくあります。

例えば、ToDoアプリでタスクを追加する場合を考えます。

1. ユーザーが画面でタスクを入力する。
2. フロントエンドがバックエンドのAPIに登録を依頼する。
3. バックエンドが内容を確認し、データベースに保存する。
4. バックエンドが処理結果を返す。
5. フロントエンドが結果に応じて画面を更新する。

### HTTPリクエストとレスポンス

HTTPは、Web上でクライアントとサーバーが情報をやり取りするためのプロトコルです。

クライアントから送る要求を**リクエスト**、サーバーから返される応答を**レスポンス**と呼びます。

例えば、タスク一覧を取得する場合は、次のようなリクエストが考えられます。

```http
GET /api/tasks HTTP/1.1
Host: example.com
```

サーバーは、タスクのデータをJSON形式で返すことができます。

```json
[
  {
    "id": 1,
    "title": "レポートを書く",
    "completed": false
  },
  {
    "id": 2,
    "title": "買い物に行く",
    "completed": true
  }
]
```

JSONは、オブジェクトや配列などのデータをテキストで表現する形式です。

JavaScriptだけでなく、PythonやJavaなど、さまざまな言語から扱えます。

### HTTPメソッド

HTTPでは、リクエストの目的を表すためにメソッドを利用します。

| メソッド | 主な用途 | ToDoアプリの例 |
| --- | --- | --- |
| GET | 情報を取得する | タスク一覧を取得 |
| POST | データを送信して処理を依頼する | 新しいタスクを登録 |
| PUT / PATCH | リソースを更新する | タスクの内容や状態を更新 |
| DELETE | リソースを削除する | タスクを削除 |

これは一般的なWeb APIの設計例であり、すべてのAPIがこの形式を採用しているわけではありません。

### ステータスコード

サーバーはHTTPレスポンスにステータスコードを含め、処理結果を伝えます。

| コード | 意味 |
| --- | --- |
| 200 OK | リクエストが成功した |
| 201 Created | 新しいリソースが作成された |
| 400 Bad Request | リクエストに問題がある |
| 401 Unauthorized | 認証が必要、または認証に失敗した |
| 404 Not Found | 対象のリソースが見つからない |
| 500 Internal Server Error | サーバー内部で問題が発生した |

## 5. ToDoアプリ全体の処理を考える

ここまでの内容を、タスク追加という一つの操作で整理してみましょう。

```text
ユーザー
   |
   | タスク追加ボタンを押す
   v
フロントエンド（ブラウザー）
   |
   | HTTPリクエスト
   | POST /api/tasks
   v
バックエンド（サーバー）
   |
   | データの検証・登録
   v
データベース
   |
   | 保存結果
   v
バックエンド
   |
   | HTTPレスポンス
   v
フロントエンド
   |
   | タスク一覧を更新
   v
ユーザーに表示
```

このように、ユーザーから見ると単純な操作でも、内部では複数の仕組みが連携している場合があります。

ここで重要なのは、フロントエンド・バックエンド・データベースが、それぞれ異なる役割を持っていることです。

## 6. ローカル環境・サーバー・クラウド

### ローカル環境

ローカル環境とは、一般に開発者自身のPCなどでプログラムを動かす環境です。

例えば、PC上で開発サーバーを起動し、`localhost` にアクセスしてWebアプリケーションを確認できます。

`localhost` は、アクセスしているコンピューター自身を指す名前です。

### サーバー

サーバーは、ほかのプログラムや端末からの要求に応じて、機能やデータを提供するものです。

サーバーという言葉は、役割を担うプログラムを指す場合も、それを動かすコンピューターを指す場合もあります。

開発者のPCでもサーバープログラムを動かせます。

### クラウド

クラウドサービスを利用すると、インターネット経由でコンピューターやデータベースなどの資源を利用できます。

代表的なサービスには、AWS、Google Cloud、Microsoft Azureなどがあります。

クラウドはプログラミング言語ではなく、アプリケーションを動かすための環境やサービスを提供するものです。

### デプロイとは？

開発したアプリケーションを、利用者が使える環境に配置・公開することをデプロイと呼びます。

例えば、ローカルで作成したWebサイトをGitHub Pagesに公開することもデプロイの一例です。

ただし、GitHub Pagesは静的サイトの公開サービスなので、任意のバックエンドプログラムやデータベースをそのまま動かせるわけではありません。

## 7. 実際のアプリケーション構成を考えてみよう

次のアプリケーションを作る場合、どのような構成が必要になるでしょうか。

### ケース1：簡単な電卓アプリ

ブラウザー上で数字を入力し、計算結果を表示するアプリ。

考えること：

- フロントエンドだけで実現できるか？
- バックエンドは必要か？
- データベースは必要か？

計算だけなら、HTML・CSS・JavaScriptを利用してブラウザー内で実現できます。

### ケース2：複数端末で同期するToDoアプリ

スマートフォンとPCの両方で同じタスクを確認できるアプリ。

考えること：

- タスクはどこに保存するか？
- 異なる端末からどうやって取得するか？
- 誰のタスクかをどう判断するか？

サーバーやクラウドサービスを通じてデータを共有し、ユーザーごとのデータを管理する構成が考えられます。

### ケース3：AIを使った画像分類アプリ

画像をアップロードすると、AIが分類結果を返すアプリ。

考えること：

- 画像のアップロードはどこで行うか？
- AIモデルはどこで実行するか？
- 分類結果はどうやって画面に表示するか？

AIモデルをサーバーで実行する構成もあれば、端末上で実行する構成もあります。

必要な性能やモデルの大きさによって設計が変わります。

## 8. まとめ

ソフトウェア開発では、複数の技術がそれぞれの役割を担いながら連携します。

- フロントエンド：ユーザーが操作する画面
- バックエンド：リクエストの処理やデータの管理
- データベース：データの保存・検索・更新
- API：ソフトウェア同士が機能やデータをやり取りするための窓口
- HTTP：Webで情報をやり取りするためのプロトコル
- デプロイ：作成したアプリケーションを利用可能な環境に配置すること

**アプリケーションを作るときは、どんな機能が必要で、それぞれをどこで動かし、どう連携させるかを考えることが重要です。**
